# Connecting programs together

Unix commands normally have:

* **standard input** — where they read data from;
* **standard output** — where they write normal results;
* **standard error** — where they write errors.

Usually the standard output is your terminal.

For example:

```sh
ifconfig eth0
```

prints its output on the terminal.

But Unix lets us take the output of one program and give it directly to another program.

For this we use the **pipe** character:

```text
|
```

For example:

```sh
ifconfig eth0 | grep ether
```

The `|` means:

> take the standard output of the command on the left and use it as the standard input of the command on the right.

So here:

```text
ifconfig eth0
        |
        v
   grep ether
```

`ifconfig` produces many lines.

`grep ether` receives those lines and prints only lines containing the word `ether`.

Try:

```sh
ifconfig eth0
```

and then:

```sh
ifconfig eth0 | grep ether
```

Compare the outputs.

What did `grep` remove?

---

```sh

```

You can experiment with it.

For example:

```sh

```

or:


# Redirecting output to a file

A pipe:

```text
|
```

sends output to **another program**.

A greater-than sign:

```text
>
```

sends output to a **file**.

For example:

```sh
ifconfig eth0 > interface.txt
```

does not print the normal output of `ifconfig` on your terminal.

Instead, it writes that output into:

```text
interface.txt
```

Check:

```sh
ls
```

Then:

```sh
cat interface.txt
```

Now combine a pipe and redirection:

```sh
ifconfig eth0 | grep ether > line.txt
```

What happens here?

First:

```sh
ifconfig eth0
```

produces information about the interface.

Then:

```text
|
```

sends that information to:

```sh
grep ether
```

`grep` keeps only the line containing `ether`.

Finally:

```text
>
```

writes that line into:

```text
line.txt
```

Check it:

```sh
cat line.txt
```

So remember:

```text
command1 | command2
```

means:

> send output from command1 into command2

while:

```text
command > file
```

means:

> write the output of command into a file

# Extract only the Ethernet address

Our file currently contains a whole line.

We want a file containing **only** the Ethernet address.

There is another useful Unix command:

```sh
cut
```

Read:

```sh
man cut
```

Try to understand what the options `-d` and `-f` mean.

You can connect more than two commands with pipes:

```text
program1 | program2 | program3
```

The output flows from left to right:

```text
program1
   |
   v
program2
   |
   v
program3
```

For example, we can:

1. ask `ifconfig` for interface information;
2. use `grep` to keep only the Ethernet line;
3. use `cut` to keep only one field.

Experiment with commands such as:

```sh
ifconfig eth0 | grep ether
```

and then try adding `cut`.

Your goal is to produce output like:

```text
18:c3:00:58:8d:47
```

and nothing else.

When you have found the correct command, redirect its output to:

```text
ether.txt
```

For example, the structure of your command will look like:

```sh
ifconfig eth0 | grep SOMETHING | cut SOMETHING > ether.txt
```

You need to figure out the missing parts.

Check your result:

```sh
cat ether.txt
```

The file should contain only one Ethernet address.

Add it to Git:

```sh
git add ether.txt
```

# What Ethernet neighbors does the server know about?

A computer sometimes needs to send an Ethernet frame to another computer on the same local network.

To send an Ethernet frame, it needs to know the destination Ethernet address.

Unix keeps information about other machines it has recently communicated with.

There is an old command for looking at this information:

```sh
arp
```

Try it:

```sh
arp
```

It is probably not found.

The program exists, but once again its directory is not in your `PATH`.

I can tell you that it is in:

```text
/usr/sbin
```

Add `/usr/sbin` to your `PATH`.

Then run:

```sh
arp
```

Now run:

```sh
arp -n
```

Compare the outputs.

What changed?

---

Look at the column containing addresses such as:

```text
18:c3:00:58:8d:47
```

What kind of addresses are these?

---

The table you are looking at is called the **ARP table**, or **ARP cache**.

It does **not** necessarily contain every computer connected to the network.

It contains neighboring machines that this server currently knows about.


```text

```

This sends the program a signal called `SIGINT`.


# Extract an Ethernet address from the ARP table

Now let's practice pipes again.

Run:

```sh
arp -n
```

Suppose you want to find only one particular line.

You can send the output to `grep`:

```sh
arp -n | grep SOMETHING
```

Replace `SOMETHING` with part of the line you want to find.

Remember:

```text
arp -n
   |
   v
 grep
```

The `arp` command does not know anything about `grep`.

It simply writes its output.

The shell connects that output to the input of `grep`.
